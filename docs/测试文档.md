## 二、场景 1：正常排班（默认数据）

**前置条件**：使用默认数据（5 类样本、6 名人员、任务总量 48 件，需求工时约 34.8h < 可用 40h）。

**操作步骤**：在"智能排班"页录入默认任务量 → 点击"智能排班"。

**实际输出**：

```
完成样本: 48/48 (100%)
用工: 36.41h / 可用: 40h
收入 ¥15100 - 直接成本 ¥6080 - 人力成本 ¥1662.71 = 利润 ¥7357.29
积压: 0 个
人员利用率：张伟 90.63% / 李娜 90.91% / 王强 96.49% / 赵敏 96.23% / 陈晨 90.28% / 刘洋 71.43%
```

**断言结果**（6 项全部通过）：

| 断言 | 结果 |
| --- | --- |
| 全部样本完成，无积压 | 通过 |
| 完成率 = 100% | 通过 |
| 无严重告警（仅 2 条工时接近上限的提示） | 通过 |
| 利润 = 收入 − 直接成本 − 人力成本 | 通过 |
| 每人实际工时不超过可用工时 | 通过 |
| 所有分配均满足技能匹配 | 通过 |

## 三、场景 2：人员状态调整后重新排班（需求 3 / 规则 6）

**前置条件**：模拟张伟、李娜两名全职员工离岗（在"人员配置"页将其状态改为"离岗"并保存）。

**操作步骤**：人员配置页修改在岗状态 → 保存 → 回到智能排班页 → 点击"智能排班"重新生成。

**实际输出**：

```
完成样本: 23/48 (47.92%)
用工: 22.4h / 可用: 24h
利润 ¥4191.85
积压: 25 个
[严重] 人力不足：25 个样本未能安排，明细：水质检测(A) 11 个、空气颗粒物检测(C) 7 个、纺织品甲醛检测(E) 7 个。
[提示] 王强/赵敏/陈晨 工时利用率接近上限。
```

**断言结果**（5 项全部通过）：

| 断言 | 结果 |
| --- | --- |
| 离岗人员未被分配任何任务 | 通过 |
| 重排后结果与场景 1 不同（重排生效） | 通过 |
| 出现告警（人力减少导致部分样本无法安排） | 通过 |
| 告警包含调整建议 | 通过 |
| 剩余人员工时仍不超限 | 通过 |

**结论**：系统能正确响应人员状态变化并重新生成排班，同时如实暴露"缺 2 人"导致的 25 件积压，告警明细逐类型列出积压数量并给出建议，符合题目需求。

## 四、场景 3：人手不足（任务量激增）

**前置条件**：任务量大幅增加（A 类 40、B 类 25、C 类 20、D 类 10、E 类 30，共 125 件，需求工时约 63h >> 可用 40h）。

**操作步骤**：在"智能排班"页将各类型任务量修改为上述数值 → 点击"工作量预测" → 点击"智能排班"。

**实际输出**：

```
完成样本: 46/125 (36.8%)
用工: 38.36h / 可用: 40h
积压: 79 个
[严重] 人力不足：79 个样本未能安排，明细：水质检测(A) 28 个、食品微生物检测(D) 5 个、
       空气颗粒物检测(C) 19 个、纺织品甲醛检测(E) 27 个。
预测：需求 63h / 可用 40h / 缺口 23h / 预计完成率 63%
```

**断言结果**（6 项全部通过）：

| 断言 | 结果 |
| --- | --- |
| 出现未完成样本（积压） | 通过 |
| 存在严重级别告警 | 通过 |
| 预测缺口工时 > 0 | 通过 |
| 预计完成率 < 100% | 通过 |
| 告警给出具体调整建议 | 通过 |
| 高优先级样本（A，P1）积压占比 70% 不高于低优先级（E，P3）的 90%，即高优先级优先安排 | 通过 |

**结论**：在严重超载时系统把有限工时优先分配给高优先级、高毛利样本（B 类 25 件全部完成），并输出准确的缺口预测与逐类型积压明细，验证了排班规则的优先级逻辑。

## 七、AI 使用说明（题目要求：AI 工具可辅助完成，但须明确说明使用情况）

### 7.1 使用的 AI 工具

QoderWork（桌面 AI 助手，本次任务中为唯一的 AI 辅助工具）。

### 7.2 AI 参与的工作内容

| 工作项 | AI 参与程度 | 说明 |
| --- | --- | --- |
| 需求理解与功能拆解 | 辅助 | AI 将题目五大需求、十一条规则、三个交付物、四个加分项整理为开发清单 |
| 排班算法设计 | AI 主导 | 由 AI 提出"硬约束过滤 + 优先级排序 + 加权评分选人"的贪心方案，人工评审确认逻辑自洽 |
| 后端代码（API/存储/算法） | AI 编写 | 约 500 行，人工逐模块审查 |
| 前端代码（5 页面 + 图表） | AI 编写 | 约 1200 行，人工审查 |
| 默认测试数据设计 | AI 设计 | 技能矩阵与任务量经实测调优（见 7.3） |
| 测试用例与断言 | AI 设计 | 17 条断言对应题目三个场景 |
| 设计/测试/运行文档 | AI 起草 | 人工校对 |

### 7.3 人工介入与修正记录

AI 并非一次输出即正确，过程中人工发现并修正了 3 个问题：

1. 测试脚本笔误：告警列表误从 `summary` 下读取导致运行报错，修正为从结果顶层读取；
2. 默认任务量不合理：初版 E 类任务 12 件时，因"技能 × 工时"交叉约束导致 2 件排不下（96% 完成率），人工分析瓶颈后调为 10 件，使正常场景达到 100% 完成；
3. 前端路由缺失：初始版本无页面深链，验收截图不便，人工提出后补充 hash 路由。

### 7.4 如何保证 AI 产物质量

1. 核心算法不依赖"黑盒"：调度逻辑拆成纯函数模块（scheduler.js），输入输出可独立测试；
2. 自动化断言：17 条断言全部通过才视为验收（运行 `npm test` 可复现）；
3. 端到端验证：API 冒烟测试 + 前端构建 + 无头浏览器截图，从接口到界面三层验收；
4. 文档与代码同步：算法设计说明直接写在 scheduler.js 头部注释中，避免"代码与文档两张皮"。
